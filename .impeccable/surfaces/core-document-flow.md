# Core document flow

Mode: Operate

## Direction contract

THESIS: A dense, dependable document workbench where shared business data becomes five consistent A4 documents; it refuses a decorative dashboard and any editor that separates form input from paper output.

OWN-WORLD: Cool neutral grey work areas, white panels and paper, deep slate text, one precise #1D4ED8 action color. Six-pixel controls, ten-pixel panels, hairline separators, tabular amounts, Noto Sans SC / PingFang SC / Microsoft YaHei. The signature move is the immediate paper response: every structured edit, language, theme, or document-type change is visible in the same A4 composition without re-entry.

STORY: The user resumes a draft or creates a document in three steps, chooses reusable customer and product records, edits only the active business block, checks the paper, and downloads a real PDF. Browser-local persistence is explicit.

FIRST VIEWPORT: On the dashboard, a compact left navigation and top bar frame a direct continue-editing row, five document-type shortcuts, and recent documents. In the editor, a 60px toolbar sits above a 176px step rail, 420px structured form, and fluid grey preview stage with a centered white A4 page; Download PDF is the sole primary action.

FORM: User-brief-pinned professional document workstation; first and only candidate because the execution draft fixes the information architecture and visual system. seed: none (unavailable)

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Finish review

VERDICT: PASS. The working editor remains the product shell; the paper is the visual center, and the committed cool-neutral palette, single blue action voice, dense forms, and responsive task flow are present without decorative dashboard patterns.

- Core flow: three-step creation, quantity/total synchronization, five-document shared data, packing-list price suppression, browser-local persistence, refresh recovery, and real PDF download passed.
- PDF: Chinese, Arabic RTL with mixed Chinese/Latin text, and two-page packing list passed; every file reports 595.28 × 841.89 pt (A4), with selectable text and repeated table headers.
- Responsive: 1280px editor and 390px dashboard/editor/preview passed without page-level horizontal overflow; mobile editing, preview tabs, and fixed download action passed.
- Runtime: no browser console errors, page exceptions, broken images, or 4xx/5xx requests during the final responsive flow; source lint passes.
- Product I/O: real CSV/XLSX import, XLSX export/re-import, field-sample download, row validation, duplicate-SKU skip/overwrite, refresh persistence, and unchanged historical snapshots passed.
- Template I/O: JSON export/re-import, invalid-package rejection, partial overwrite confirmation, template editing, all default fields applied to a real new document, and legacy local-data migration passed.
- Import/template responsive review: 1280px and 390px layouts passed without page-level horizontal overflow; the mobile import preview remains internally scrollable.
- Template live preview: the wide settings/A4 workspace reuses the production paper component; language, currency, theme, terms, images, bank details, demonstration stamp, and packing-price columns update immediately. Cancel/save boundaries and mobile edit/preview tabs passed at 1440px and 390px.

ASSET PROVENANCE: The QOSA logo was recovered from the user's public QOSA LPG weekly report repository, recolored for white paper while preserving its transparent background and original letterforms, and embedded as a text data URI for offline HTML/PDF use. Application icons use the product's own geometric SVG document mark. No external stock raster, real company seal, or commercial proof asset is shipped. PDF fonts are restored from npm Noto packages; QOSA is the user's company identity, while demonstration customers, products, and transactions are explicitly fictional.
